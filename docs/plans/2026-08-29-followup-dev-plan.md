# 后续开发方案：从「演示 MVP」到「可信可用的岗位情报 + 简历工具」

> 日期：2026-08-29
> 依据：2026-08-29 第一性原则整体对抗审查（四路：后端 / 前端 / 完整度 / 安全）
> 定位：方向级方案。技术实现由开发工具自由发挥，本文只规定目标、范围、边界与验收。

## 0. 背景结论（为什么要做）

- 功能链路已全通：注册 → 抓取 → 岗位库 → 匹配 → 草稿 → 审阅 → 导出，门禁（后端 pytest、前端 test/typecheck/build）全绿。
- 但核心承诺当前是“演示级”：
  - 主库 88 条岗位中 68 条是 generic 占位正文，45 条来自已禁用机构；
  - 6 个真实适配器最近跑批仅 3 家有产出，其余静默返回 0；
  - 无每日自动抓取，调度器只扫订阅；
  - 存在可一次性击穿“真实简历”承诺的路径（示例假数据可保存导出、审阅完成默认全采纳）；
  - 部署链路过时（明文 HTTP、无固定密钥、缺中文字体、工具链不匹配、构建配置未入库）。

## 1. 总原则

1. 优先级：**数据真实 > 功能完整 > 可用性 > 部署安全 > 质量体系**。
2. 每个交付以“核心承诺可被证伪”为验收基准：岗位必须可溯源，简历内容必须逐项绑定用户事实。
3. 技术自由：不指定实现方式，但每项都必须提供行为化验收证据。
4. 边界（红线，任何阶段不得突破）：
   - 不接第三方招聘平台账号、不做登录采集、不做反爬对抗；
   - 不把 LLM 作为核心匹配 / 简历生成依赖；
   - PDF 附件表格解析不做，除非带 fixture 与测试；
   - 示例/演示数据不得静默进入正式档案与导出；
   - 岗位占位数据不得冒充真实数据；
   - 不改 raw 数据、不跑 git、不装依赖、不做全库格式化。

## 2. 阶段 A：数据真实化（最高优先级）

### A1 岗位数据资产清洗与分级
- 目标：岗位库里每一条要么真实可溯源，要么被明确标记为演示/未复核。
- 方向：
  - fixture、generic 占位、已禁用机构历史数据从“默认岗位库”分流；
  - 岗位库默认只展示启用机构 + 新鲜度窗口内的真实记录；
  - 占位/旧数据在分析与匹配中可被过滤或单独切片。
- 验收：打开岗位库看不到“该记录由通用列表解析器抽取”被当作真岗位；分析页可按数据可信度过滤。

### A2 六个真实适配器可用化
- 目标：官方适配器“每次跑批要么有产出，要么明确报错”，杜绝静默 0。
- 方向：
  - 零产出视为失败并记录原因；
  - 站点结构变化可告警；
  - 适配器真实数据与 fixture 演示数据彻底隔离。
- 验收：最新 12 机构跑批中，6 家真实适配器每家都有岗位或都有可见失败原因；连续失败在分析页可查。

### A3 自动更新闭环
- 目标：数据每天自动刷新，订阅每天自动扫描。
- 方向：定时抓取 → 去重更新 → 订阅扫描 → 健康度记录 → 失败告警；单飞、重试、进度与结果可见。
- 验收：连续 7 天无人值守，每天有新数据或可解释失败；用户可见上次抓取时间与新鲜度。

### A4 溯源与快照
- 目标：任意岗位可回答“何时、从哪个 URL、哪个解析器抓的、当时正文是什么”。
- 方向：
  - 岗位身份绑定机构 + URL + 解析器，而非只看正文哈希；
  - 同 URL 内容更新保留历史版本；
  - 两家机构相同公告不得互相吞并或错挂。
- 验收：公告改版后仍可查历史正文；镜像公告不被误归属。

## 3. 阶段 B：功能完整性收敛

### B1 数据健康视图
- 方向：解析器健康度支持“连续失败 / 持续下降”，而非单次快照；失败可见、可一键重跑。
- 验收：连续 N 天失败的适配器出现 review 状态并给出操作入口。

### B2 订阅真正可用
- 方向：订阅从“计数 + 时间戳”升级为有真实触达（站内通知 / 摘要 / 邮件任选其一）；关键词边界（中英文、空词、宽泛词）处理；机构维护状态下禁止或提示新建订阅。
- 验收：新岗位入库后订阅者在目标渠道能收到内容摘要。

### B3 简历审阅与导出闭环
- 方向：
  - 每项内容在导出前必须有用户明确决定，未决策项不得默认通过；
  - 导出内容逐项绑定档案证据，无证据项硬拦截或显式确认；
  - 诊断模式覆盖 DOCX 与 PDF。
- 验收：“完成审阅”不等于“全部采纳”；应聘版导出不出现无证据/未确认内容。

### B4 档案入口防呆
- 方向：示例/演示数据与真实档案严格隔离；示例加载需确认并带“演示数据”标记。
- 验收：误点示例不会让假姓名/假电话进入已保存档案及导出。

### B5 分析与报告
- 方向：报告可筛选、保存回看、导出；每个数字附带样本范围；失败态不渲染成 0。
- 验收：分析页每个指标都有数据来源与时效解释。

## 4. 阶段 C：可用性工程

### C1 首用流程
- 方向：登录后明确路径：抓数据 → 选岗位 → 填/导入档案 → 审阅 → 导出；每步前置条件清晰。
- 验收：新用户不看文档可走完整流程。

### C2 状态一致性
- 方向：筛选、翻页、切岗位、切页面必须同步或清空当前上下文；禁止“显示岗位 B 却导出岗位 A 草稿”；未保存修改有离开拦截与恢复提示。
- 验收：上述操作交叉反复后，界面始终与用户当前选择一致。

### C3 错误处理三态
- 方向：所有网络/保存/删除/导出操作有 loading、成功、失败三态；无响应体接口约定全链路一致；失败原因可读。
- 验收：删除订阅成功即更新列表；保存失败不丢输入；导出失败有可操作提示。

### C4 可访问性与响应式
- 方向：键盘可完成核心操作；对话框有语义与焦点管理；小屏下岗位库/筛选/详情抽屉可用。
- 验收：纯键盘走通“选岗位 → 审阅 → 导出”；手机宽度无横向爆版。

### C5 空/错/边界态
- 方向：岗位为空、匹配为空、档案为空、导出被拦截均有解释 + 下一步按钮。
- 验收：清空数据后每个页面仍友好且有引导。

## 5. 阶段 D：部署、安全、复现

### D1 一键部署可用
- 方向：部署脚本与当前工具链一致；CJK 字体、环境变量齐全；数据库路径统一；启动文档与实际一致。
- 验收：新服务器一键部署后 PDF 可导出、重启登录不失效。

### D2 传输与密钥
- 方向：默认 HTTPS；固定 `AUTH_SECRET`；token 存储与传输按安全基准。
- 验收：无明文口令链路；无“重启全员掉线”默认行为。

### D3 爬虫安全
- 方向：TLS 校验开启；出站目标限官方域名；禁私网/云元数据地址；限制重定向与响应大小。
- 验收：被污染页面无法让服务器访问内网；抓取内容不可被中间人篡改。

### D4 防滥用
- 方向：登录限速/锁定；爬虫与外部调用端点登录 + 配额 + 单飞；上传大小限制。
- 验收：匿名无法触发抓取或外部调用；爆破与超大上传不可行。

### D5 CI 与复现
- 方向：PRD、计划、评审文档全部入库；前端构建配置入库；CI 自动跑门禁与依赖审计；新机器可按文档复现。
- 验收：克隆 → 依文档启动 → 门禁全绿，不依赖本机遗留配置。

## 6. 阶段 E：质量与可维护性

### E1 测试面补齐
- 方向：关键路径组件/API 级测试：登录、204、401、删除订阅、导出拦截、筛选/切岗状态、示例档案护栏。
- 验收：本次审查 P0/P1 场景均有回归测试。

### E2 匹配评测扩容
- 方向：真实公告 + 人工标注扩匹配集；端到端回归（公告 → 分段 → 匹配 → 草稿 → 导出）。
- 验收：红线在真实公告样本上可复现。

### E3 可观测性
- 方向：抓取、调度、解析器、导出失败可查；不允许静默吞异常。
- 验收：后台任务失败可定位到原因。

### E4 文档同步
- 方向：README/runbook/AGENTS 与真实行为一致；交接文档随阶段更新。
- 验收：文档命令在全新机器可用。

## 7. 里程碑

| 里程碑 | 内容 | 完成标志 |
|---|---|---|
| M1 数据真实化 | A1–A4 | 岗位库无占位冒充、6 适配器有产出或明确失败、自动抓取每天跑、溯源可查历史 |
| M2 功能闭环 | B1–B5 + D1–D2 | 订阅可触达、审阅=真审阅、示例隔离、一键部署可用 |
| M3 可用性收敛 | C1–C5 + D3–D5 | 首用无死路、状态不错乱、键盘/小屏可用、CI 全绿、新机器可复现 |
| M4 质量加固 | E1–E4 | 关键路径测试覆盖、匹配评测扩集、可观测、文档同步 |

## 8. 建议提交单元（一个单元一个 commit）

- U1 可用性快修组：删除订阅 204 处理、筛选/切岗状态残留、保存失败不丢内容。
- U2 岗位库数据防线：默认只显示启用机构 + 新鲜数据，占位数据降级标记。
- U3 示例档案与审阅门禁：示例确认与演示标记；审阅完成不自动全采纳；导出前逐项证据校验。
- U4 适配器可用化：零产出=失败、结构变化告警、fixture 隔离。
- U5 自动抓取闭环：定时抓取 → 订阅扫描 → 健康度，单飞/重试/可见。
- U6 溯源与快照：岗位身份键、历史正文、去重修复。
- U7 订阅触达：真实渠道与关键词边界。
- U8 部署/复现：脚本、环境变量、字体、DB 路径、CI。
- U9 可用性工程：错误三态、键盘/弹窗、响应式、空态。
- U10 质量体系：关键路径测试、匹配评测扩容、可观测、文档同步。

## 9. 每个单元的交付与验收方式

1. 行为化验收证据（例如：删除订阅后列表更新；切岗位不会导出旧草稿；示例数据带确认；无字体环境 PDF 给出明确报错而非 500；匿名触发爬虫被拒）。
2. 全部门禁复跑结果。
3. 改动文件清单 + 提交信息（conventional commits，中文）。
4. 本单元未解决的问题与下一个单元建议。

## 10. 建议的第一步（最短路径）

1. U1 可用性快修组；
2. U2 岗位库数据防线；
3. U3 两条核心承诺防线；
4. U5 自动抓取闭环。
