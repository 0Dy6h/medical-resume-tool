# End-of-Day Handoff — 2026-07-26

## Goal

Apply first principles to the repo: read the project, find what actually makes
the core unusable, and fix it with real-run verification — no LLM key available,
so everything shipped had to be provable offline.

## Starting state (important)

`main` was **red on checkout**. The P0-1 typed-Profile merge had deleted
`RegisterPayload` / `LoginPayload` / `AuthOut` from `schemas.py`, so the backend
could not even import, and 7 tests written against the old dict profile failed.
A first-principles audit (5 parallel readers + 3 design proposals + synthesis)
then mapped the rest.

## Completed this session (each traceable to a verified defect)

1. **Repaired red main** (`fix: repair broken main…`). Restored the three auth
   schemas; finished the half-done typed-Profile test migration. 107 → green.

2. **Profile save/load contract** (`fix: make the profile save/load contract…`).
   - Legacy profiles hard-bricked the account: `get_profile` raised an uncaught
     `ValidationError` (HTTP 500) on any pre-typed row (e.g. free-text 熟练度),
     taking profile/drafts/exports down with it. `from_legacy_dict` now maps
     known levels, degrades unknowns to None, and salvages entry-by-entry.
   - Adding a row in the editor 422'd (every field was required). Item fields
     are optional now; the real invariant (a persisted item is not blank) moved
     to `to_profile()`; blank rows are dropped.
   - `作者` textarea sent a list where `authors` is a str → 422. Now coerced.
   - Import confirm dropped accepted review items (read pre-merge state). Merge
     extracted to unit-tested `frontend/src/lib/importMerge.ts`.

3. **Export path stopped deleting/truncating real facts** (`fix: stop the resume
   export…`). One incidental keyword match erased work history, publications,
   certificates and teaching from the submitted DOCX; publications rendered as a
   bare year; internal ids were cited as "evidence". All three fixed and proven
   by exporting a real DOCX and reading it back.

4. **Rebuilt Chinese requirement matching** (`feat: rebuild Chinese requirement
   matching…`). New `backend/app/services/matching/`:
   - `segment.py`: requirement extraction went from 31% boilerplate to 0% on the
     fixtures; numbered lists that lost their line breaks are split; the
     name-table fixture returns nothing with a warning instead of a fabricated
     `岗位提到：护理`.
   - `tokenize.py`: CJK bigrams (Chinese has no spaces — the old matcher's fatal
     bug). `scorer.py`: IDF-weighted overlap (committed table) + concept lexicon.
   - Guarded by `test_matching_eval.py`: **14/14 top-1, held-out 6/6, zero
     wrong-source, zero false positives, 100% traceability.**

5. **Arithmetic degree gate** (`feat: add an arithmetic degree gate…`). 学历 is
   the most common requirement and is ordinal, which similarity cannot evaluate
   (a 本科 and a 硕士 profile score identically against a 硕士 requirement that
   also mentions 本科). The gate compares 大专<本科<硕士<博士 and emits a
   **blocking** gap when the applicant is categorically ineligible — something
   the product could not say before. Surfaced in the ResumePage 缺口 panel.

## Deferred (with reasons — not skipped silently)

- **LLM lane (`jd_structurer.py`, grounded rewriting)**: no API key in this
  environment, so nothing there is real-run verifiable. The offline matcher is
  now good enough that this is an enhancement, not a dependency. Needs a provider
  + budget decision (see `docs/remediation-plan-2026-06-22.md` risks).
- **Major / certificate / age gates**: degree was the highest-value gate; the
  others follow the same pattern in `matching/gates.py` when wanted.
- **Import cross-collection fan-out**: one work block still auto-imports as
  experience + a fabricated project + publication. Needs a routing redesign
  (score all candidates, keep the best), not a patch.
- **Import → `basics` extraction**: name/phone/email still land in
  `unassigned_blocks`; the fields exist and wait to be populated.
- **`classifier.extract_requirements`**: left untouched on purpose — it writes
  the persisted `jobs.requirements` column and job filters; replacing it needs a
  data migration.
- **HTTPS + fixed `AUTH_SECRET` on the server**: ops, not repo code. Do not enter
  real PII on the HTTP demo.

## Recommended next step

Import-side routing (basics extraction + stop the experience→project/publication
fan-out): it is the remaining place the product invents or misfiles user data,
and it is fully offline-verifiable. Then decide the LLM provider/budget if
grounded rewriting is still wanted.
